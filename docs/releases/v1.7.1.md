Panely for macOS 1.7.1 updates comic OCR and reduces waiting when translating. Japanese text is read with manga-ocr, and Chinese, English and Korean with PP-OCRv5 mobile. Completed balloons reach the translator while later balloons are still being read. Opening the translation panel prepares the installed Gemma model ahead of use, and the model stays available longer between requests. This update also improves page retries, library updates and archive loading.

## Download and update

Download **Panely-1.7.1.zip** below, unzip it and drag `Panely.app` to `/Applications`. For first-launch instructions, see the [installation guide](https://github.com/sejoung/Panely/blob/main/README.md#installing-a-release).

**Updating from 1.7.0:** your library, reading positions, bookmarks and balloon edits are kept. The translation download now includes about **160 MB of OCR models**. If Gemma is already installed, only missing files are downloaded; the 3.35 GB translation model does not need to be downloaded again. A fresh installation downloads about **3.51 GB** in total. Files are checked against pinned sizes and SHA-256 hashes before installation.

Translation caches distinguish the new OCR pipeline from the previous one, so books can need translation again after the OCR pack is installed. Your saved balloon edits are kept.

## Comic OCR

- **Japanese:** manga-ocr int8, including vertical text.
- **Chinese, English and Korean:** PP-OCRv5 mobile, also used for line finding and language detection. The existing RT-DETR model continues to locate balloons and text regions on the GPU.
- **Reading and translation overlap.** Complete balloon groups are passed to Gemma as they become ready, without waiting for all OCR on the page. Lines belonging to the same balloon stay together.
- **More work per inference call.** Line detection uses four CPU threads. PP-OCR reads up to eight lines of the same input width together, preserving each crop's resolution and padding and restoring the original line order.
- **Normal startup skips Vision language-model preparation.** Apple Vision remains a fallback when comic OCR is unavailable or fails before publishing results. The first use of that fallback can still take time.

### Measured OCR performance

On the development Apple Silicon Mac, 24 Korean comic pages at 1500×2109 were processed twice per configuration in an optimized Debug build. Mean OCR time fell from **0.793 to 0.631 seconds per page**, about **20%**, when moving from two detector threads and single-line reading to four threads and batched reading. Recognized text, region geometry and order matched across all configurations.

This compares settings within the new OCR pipeline, not the previous Vision engine. It measures OCR alone, without simultaneous Gemma generation, and does not imply the same improvement in total book translation time or on every Mac. The detector's 2400-pixel resolution cap is retained. See [measurement details and reproduction commands](https://github.com/sejoung/Panely/blob/main/docs/ocr-pipeline.md).

## Translation responsiveness and recovery

- **Preparation starts when the panel opens.** An installed Gemma model loads on its own executor. Reopening the panel and starting a job reuse the loaded model. Opening the panel does not start a translation or download a model.
- **Ten-minute reuse window.** Gemma is released after ten idle minutes, increased from two, reducing reloads during short reading breaks. Its roughly 3.5 GB of mapped model memory stays in use longer. Cold loading still takes time if translation starts before preparation finishes.
- **Failed pages get another attempt.** They are retried after the remaining pages. Persistent failures are reported, and starting translation again processes the unfinished pages.
- **Choose the book's language while detection is pending.** The language control appears near the top of the panel until the source language is known. Choosing a language after detection fails starts the waiting job.

## Reader and library performance

- Reduce repeated work when updating the library sidebar, reading progress, thumbnails and translation overlays.
- Share in-flight image decodes and cancel reads that are no longer needed during rapid page changes.
- Reuse cached solid-RAR extraction when reopening a book, and batch image-header reads from ordinary RAR archives.

## Verification and diagnostics

- The local Debug run passed **1,088 tests**; the separate real-Gemma suite passed **5 tests**. Real-model OCR tests cover the supported readers, vertical Japanese and batched-versus-single-line output.
- `scripts/test.sh` is the shared local and CI runner, with suite selection, independent repeat runs and saved commands, full logs and `.xcresult` bundles. CI retains the test artifacts.
- Diagnostics now separate OCR preprocessing, session loading, inference, postprocessing and reading, along with Gemma backend initialization, model loading, context creation and warm-up.

## 한국어

Panely macOS 1.7.1은 만화 OCR을 바꾸고 번역할 때 기다리는 시간을 줄입니다. 일본어는 manga-ocr로, 중국어·영어·한국어는 PP-OCRv5 mobile로 읽습니다. 뒤쪽 말풍선을 읽는 동안 인식이 끝난 말풍선부터 번역합니다. 번역 패널을 열면 설치된 Gemma 모델을 미리 준비하고, 요청 사이에도 더 오래 재사용합니다. 실패한 페이지 재시도, 라이브러리 갱신과 압축 파일 로딩도 개선했습니다.

### 내려받기와 업데이트

아래 **Panely-1.7.1.zip**을 내려받아 압축을 풀고 `Panely.app`을 `/Applications`로 옮깁니다. 처음 실행하는 방법은 [설치 안내](https://github.com/sejoung/Panely/blob/main/README.ko.md)를 참고하세요.

**1.7.0에서 업데이트:** 라이브러리, 읽던 위치, 북마크와 말풍선 수정 내용은 그대로 남습니다. 번역 모델 다운로드에 **OCR 모델 약 160MB**가 추가됩니다. Gemma가 이미 설치돼 있으면 없는 파일만 받으므로 3.35GB 번역 모델을 다시 받을 필요가 없습니다. 새로 설치할 때는 합계 약 **3.51GB**를 받습니다. 설치 전에는 고정된 크기와 SHA-256 해시로 파일을 확인합니다.

번역 캐시는 새 OCR 경로와 기존 경로를 구분하므로, OCR 팩 설치 후 책을 다시 번역해야 할 수 있습니다. 저장한 말풍선 수정 내용은 유지됩니다.

### 만화 OCR

- **일본어:** manga-ocr int8로 읽으며 세로쓰기도 지원합니다.
- **중국어·영어·한국어:** PP-OCRv5 mobile로 읽고, 글줄 검출과 언어 감지에도 사용합니다. 말풍선과 글자 영역은 기존 RT-DETR 모델이 GPU에서 찾습니다.
- **인식과 번역을 겹쳐 실행합니다.** 페이지 전체 OCR이 끝나기를 기다리지 않고, 인식이 끝난 말풍선 묶음부터 Gemma에 넘깁니다. 같은 말풍선의 줄은 함께 처리합니다.
- **한 번에 여러 줄을 읽습니다.** 글줄 검출에는 CPU 스레드 4개를 쓰고, PP-OCR은 입력 폭이 같은 줄을 최대 8개씩 묶어 읽습니다. 각 영역의 해상도와 여백을 유지하고 결과는 원래 줄 순서로 돌려놓습니다.
- **일반 시작 과정에서 Vision 언어 모델 준비를 건너뜁니다.** 만화 OCR을 사용할 수 없거나 결과 전달 전에 실패하면 Apple Vision을 대체 경로로 사용합니다. 이 대체 경로의 첫 실행에는 시간이 걸릴 수 있습니다.

### OCR 속도 측정

개발용 Apple Silicon Mac에서 1500×2109 크기의 한국어 만화 24페이지를 설정별로 두 번씩 처리했습니다(최적화한 Debug 빌드). 검출 스레드 2개·한 줄씩 인식하는 설정에서 스레드 4개·묶음 인식으로 바꾸자, 페이지당 평균 OCR 시간이 **0.793초에서 0.631초로 약 20% 줄었습니다.** 모든 설정에서 인식 문장, 영역 위치와 순서가 일치했습니다.

이는 **새 OCR 내부의 설정 비교**이며, 기존 Vision 엔진과의 비교는 아닙니다. Gemma 번역을 동시에 실행하지 않은 OCR 단독 측정이므로, 책 전체 번역 시간이나 모든 Mac에서 같은 개선을 보장하지는 않습니다. 검출 해상도 상한은 기존 2400픽셀을 유지했습니다. [측정 내용과 재현 명령](https://github.com/sejoung/Panely/blob/main/docs/ocr-pipeline.md)을 참고하세요.

### 번역 대기와 실패 복구

- **패널을 열 때 미리 준비합니다.** 설치된 Gemma 모델을 전용 실행기에서 불러옵니다. 패널을 다시 열거나 번역을 시작할 때 이미 불러온 모델을 재사용합니다. 패널을 여는 것만으로 번역이나 모델 다운로드를 시작하지는 않습니다.
- **10분간 재사용합니다.** 모델을 사용하지 않을 때 해제하기까지의 시간을 2분에서 10분으로 늘려, 잠깐 읽고 다시 번역할 때 재로딩을 줄입니다. 약 3.5GB의 모델 메모리도 그만큼 오래 유지됩니다. 준비가 끝나기 전에 번역을 시작하면 첫 로딩을 기다릴 수 있습니다.
- **실패한 페이지를 다시 시도합니다.** 나머지 페이지를 처리한 뒤 실패한 페이지를 재시도합니다. 계속 실패한 페이지는 개수를 알려 주며, 다시 번역하면 아직 끝나지 않은 페이지를 처리합니다.
- **언어 감지를 기다리는 동안 직접 고를 수 있습니다.** 책의 언어가 확인되기 전에는 패널 위쪽에 선택 항목을 보여줍니다. 감지에 실패한 뒤 언어를 고르면 기다리던 번역이 시작됩니다.

### 뷰어와 라이브러리 성능

- 라이브러리 사이드바, 읽기 진행도, 썸네일과 번역 오버레이를 갱신할 때 반복하는 작업을 줄였습니다.
- 진행 중인 이미지 디코딩을 공유하고, 빠르게 페이지를 넘길 때 더 이상 필요 없는 읽기를 취소합니다.
- solid RAR 책을 다시 열 때 추출 캐시를 재사용하고, 일반 RAR의 이미지 헤더는 모아서 읽습니다.
